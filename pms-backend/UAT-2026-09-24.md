## Decisions and limits for UAT review

- Existing records are not automatically classified. They show **Needs classification** and are excluded from classified KPI counts/amounts until an authorized user reviews them. No NDC amount is inferred from total project cost.
- New records require classification in the web form. The API accepts omitted/null classification for compatibility with older clients and imported data.
- Once a classified record has any approval or fund-release record, the API prevents reclassification. Existing project editing permissions and approval locks still apply.
- Narrative controls support plain text, editable tables and uploaded images. They do **not** provide inline drawing, chart generation or a full word-processing toolbar. This is the implementation assumption for the checklist's shapes/graphs/charts comments and needs business UAT confirmation.
- Each narrative section allows up to 5 tables (50 rows × 12 columns, 2,000 characters per cell) and 3 images. Images require captions and valid PNG/JPEG/WebP content, at most 500 KB and 4096 × 4096 pixels. SVG/HTML are not accepted as images. Tables render escaped text. Images are stored inside the project's structured JSON and follow existing project access rules.
- Investment lifecycle uses the latest **origin** approval workflow. “Board approved” requires an approved/approved-with-conditions record for its final configured Board-role step. Initial Board clearance alone does not qualify.
- “Investment Portfolio” additionally requires a positive fund-release amount with `status=released`. This treats the existing release ledger as NDC deployment evidence. A draft release does not qualify. It does not infer historical deployments from estimated cost or a monitoring status.
- Rejected, disapproved or cancelled latest origin approvals display **Not Proceeding** and are excluded from Under Evaluation. Returned approvals can re-enter evaluation. Records without approval evidence remain Under Evaluation once classified as investments.
- Total NDC Investment / Exposure is **recorded planned participation**, grouped by currency; it is not a market valuation or an outstanding-balance calculation. Released funds remain a separate metric. PHP investment breakdowns include only PHP investment records; different currencies are not added together.
- Additional coverage areas have region/province/address data, not separate coordinates. Only records with a primary map pin appear on the map. Location codes use the existing location catalog UI; the API validates shape/length but does not independently verify province/region catalog membership.

## API additions

Existing Sanctum authentication and project visibility/editing permissions remain in effect.

| Endpoint | Additions |
| --- | --- |
| `POST /api/projects` | Accept new project detail fields; return the created ProjectResource (`201`). |
| `PUT /api/projects/{project}` | Accept updates to the same fields (`200`). Omitted fields retain existing values. `additional_locations: []` clears extra locations. |
| `GET /api/projects`, `GET /api/projects/map`, `GET /api/reports/projects` | Accept `record_type` and `investment_status` filters. Existing pagination applies except the map endpoint. |
| `POST /api/reports/export` | Accept the same filters; optional columns include `record_type`, `investment_status`, `operations_start_date`, `additional_locations`, `other_financing`. |
| `GET /api/monitoring-reports` and its `/export`, `/export/pdf` variants | Accept classification/lifecycle filters. Project metadata and exports include classification/lifecycle labels. |
| `GET /api/dashboard/stats` | Add classified KPI counts, `ndc_investment_by_currency`, `investment_amount_missing`, and `unclassified_records` under `portfolio_summary`. Existing `estimated_investment` now means classified PHP NDC participation. |

`record_type` filter values: `project`, `investment`, `unclassified`. Stored classification values are `project`, `investment`, or null. `investment_status` filter values: `under_evaluation`, `board_approved`, `portfolio`, `not_proceeding`; this status is derived and cannot be directly written.

Example additional request fields:

```json
{
  "record_type": "investment",
  "project_type_other": "Strategic partnership",
  "industry_other": "Emerging industry",
  "sector_other": "Cross-sector",
  "operations_start_date": "2027-01-15",
  "estimated_cost": 5000000,
  "ndc_participation": 1000000,
  "currency": "PHP",
  "other_financing": [{"source": "Loans", "amount": 4000000}],
  "additional_locations": [{
    "region_code": "040000000", "region_name": "Region IV-A",
    "province_code": "042100000", "province_name": "Cavite",
    "address": "Province-wide coverage"
  }],
  "narrative_content": {
    "description": {
      "tables": [{"caption": "Capacity", "rows": [["Year", "Output"], ["2027", "1000"]]}],
      "images": []
    }
  }
}
```

The example supplements the existing required create fields. Other narrative keys are `project_rationale`, `company_background`, `target_beneficiaries`, and `expected_benefits`. Image objects use `caption` and a `data:image/...;base64,...` string in `data`. Monetary values must be non-negative; each other-financing row requires a source and amount. Selecting Others in a catalog requires its matching explanation. API validation returns `422` with field errors; unauthenticated requests return `401`, permission failures `403`, and missing records `404`.

## Migration and rollout

Two new migrations:

1. `2026_09_24_000001_add_uat_project_details.php`: nullable project metadata, classification index and indexed `project_locations` table; insert missing lookup choices.
2. `2026_09_24_000002_deactivate_sample_investment_criterion.php`: deactivate only the identified placeholder without deleting it.

Both have been applied to the **local** development database. No production deployment, production classification or mass reseeding was performed.

On another environment, back up the database, deploy backend code and run `php artisan migrate --force` from `pms-backend` before releasing the updated frontend. Use the project's normal frontend build/release process. No new environment variables, queues or scheduled jobs are required. Ensure request-body limits accommodate narrative JSON; the repository's nginx gateways allow 50 MB, while PHP/proxy settings in a target environment still need checking. Image-heavy records increase JSON response sizes because existing list/edit flows use the complete project resource.

Review and classify existing records through authorized edits. Validate recorded NDC amounts, currencies, Board evidence and release history before relying on portfolio counts. There is no automatic financial backfill.

Rolling back the schema migration deletes the newly entered metadata and extra locations. Back up that data first. Lookup choices remain to avoid breaking references. The sample criterion deliberately remains inactive on rollback; an administrator can review it manually.
